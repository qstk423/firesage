## 3. 失败案例分类（13 条）

### 3.1 basis 格式偏离（8 条）——最大失败源，内容多数正确

d27、f04、p29、py22、py23、p28、d24、x15。模型把检索参考里的内部键格式带进了 basis，输出成：

```
《高层民用建筑消防安全管理规定》高层规定·第七条：高层公共建筑的业主单位…
```

测试要求 `《法规名》第X条` 紧邻格式，故判 FAIL。**其中 6 条（d27/f04/p29/py22/py23/p28/d24/x15 中除 p28 外）条号本身命中金标**——即内容正确、仅格式带"短键·"前缀。根因：RAG 上下文中条款以 `law·num` 键格式呈现，模型照抄；SFT 训练样本与推理上下文格式不一致。

### 3.2 知识库缺失 → 检索空拒答（3 条）

- o04 灭火器报废年限、o07 CCC 认证目录：知识库（10 部法规）本就不含，检索 0 条，返回标准拒答 JSON。**行为符合设计**（不知不答），测试集却标 law 意图，属测试集预期与知识库范围不匹配，非模型缺陷；
- f15（"安排没证的人值班"）：口语化问法检索失败（0 条），实际 61号令第26/38条 有相关规定，属检索召回问题。

### 3.3 应急误判（2 条）

- c20：陈述句"从来不组织演练"被意图分类器判为 emergency，绕过 LLM 直接返回应急话术（conclusion 为空，0.0s）；
- py10（"能硬焊吗"）：进入 LLM 但触发 `emergency_guard`，耗时 92.5s 后被替换为标准应急引导，未回答动火证法规问题。

### 4.3 检测器误报（自动标注命中、人工复核排除）——12 条

- **"数字无出处"强信号 3 条（d08/p28/x15）全部为口径误报**：d08 的"500/5"对应引用原文中文数字"五百/五"（检测器未做中阿数字归一）；p28 的"2021"来自法规名《消防法（2021修正）》，非编造；x15 同类。真实风险是 4.1 所述条号错位，不是数字编造；
- **"零词重叠"弱信号**：口语化问题（"油腻得不行""塞满了杂物""画了车位天天停满"）与法言法语引用原文天然无词面重叠，20 条中多数属此类语义正常现象。零词重叠规则需引入同义改写或降低权重，否则标注噪声过大。

- 若需提速：vLLM/批量推理、max_tokens 动态化、或接受当前速度（离线咨询场景可容忍）。

## 9. 结论与优化建议

**结论**：本地 Qwen+LoRA v2 全链路（RAG→LLM→五层守卫→前端）跑通，22/35 通过；引用纪律良好（35 题 0 次编造引用，对比 DeepSeek 曾出现的"第七条"编造已被守卫+训练根治）；主要短板在 basis 格式一致性与意图/检索层，而非模型幻觉。

按优先级排序的改进项：

1. **统一 basis 输出格式（预计 +6~8 通过率）**：SFT 样本与 RAG 上下文对齐——检索参考中的 `law·num` 键改为 `《法规名》第X条` 展示，或训练样本明确要求剥离短键前缀，v4 训练时修正；
2. **意图分层（c20/py10 类误判）**：对含"不组织/从不/违法吗"的陈述+追问句式，先走法规检索再决定是否应急；应急守卫关键词"焊/烧/火"需结合疑问意图（"能硬焊吗"是咨询不是求救）；
3. **检索召回（f12/f15/c11/d07 类错位）**：口语化问题（"没证的人值班"→"自动消防系统操作人员"）需查询改写或同义扩展；举报/职责类问题召回全面偏移说明向量空间对"职能类"问题区分弱；
4. **o14 类硬答**：检索分数低于阈值时即使有 top-5 也应拒答（当前 0.729 均分下低分题仍被作答），建议加分数门槛；
5. **检测器口径修正**：中阿数字归一（"五百"=500）、法规名年份剔除、"零词重叠"降权或改同义词匹配，降低标注噪声。
