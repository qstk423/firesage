### M1 · 手写 BM25 与 RRF 融合

**你项目里的对照物**：单路向量召回，`similarity_search_with_score` 一把梭。

**这里多做了什么**：三路并行（BM25 / 向量 / 图谱），用 RRF 按**排名**融合而不是按分数，再过 CrossEncoder 精排。

顺带说破一件事：LangChain 的 `EnsembleRetriever` 内部用的就是 RRF，常数也是 60。你用过，只是没人告诉你它叫什么。

**练习 M1**：新建一个空文件，**不许用任何检索库**（不许 sklearn、不许 rank_bm25），
用纯 Python 实现 BM25，语料就用 `backend/data/chunks.json`。
然后再手写 RRF，把你自己的 BM25 和项目里现成的向量召回融合起来。

必须能回答：
1. BM25 里 `k1` 和 `b` 各控制什么？`b=0` 意味着什么？
2. 为什么 RRF 用排名而不是分数？（提示：想想你那个 `1 - d/sqrt(2)` 和 BM25 分数怎么相加）
3. `RRF_K = 60` 调成 0 会怎样？调成 1000 呢？

**通过标准**：你的手写 BM25 对同一个问题，top3 和项目里的 BM25 有明显重合。

**顺手修的历史遗留**：你项目里 `1.0 - distance / math.sqrt(2.0)` 是线性近似，
单位向量下准确关系是 `cos = 1 - d²/2`。这意味着你那个 `retriever_score_threshold`
实际卡的位置和你以为的不一样。改完对比一下过滤掉的文档有什么变化。

### M2 · 生成后核验（你项目里完全没有对应物）

**你项目里的对照物**：无。`response_parser.py` 只解析格式，不检查内容对不对得上检索到的文档。

**这里多做了什么**：`rag/verifier.py` 的 `verify()` 拿回答和依据条款逐项对照，5 条规则：
条款存在性、处罚金额一致、处罚主体匹配、建筑适用性、处罚意图覆盖。
失败 → 带反馈重生成一次 → 再失败 → 弃用 LLM 回答降级为原文摘录。

**练习 M2（当前进行中）**：修 `_extract_cited_articles` 的交叉配对 bug。

现象：它分别检查「法规名出现过吗」和「条号出现过吗」，两个独立成立就算命中。
于是答案同时引用两部法规时，会交叉配出不存在的引用，被误判成「编造」。

复现：
```bash
cd backend && python3 -c "
from rag.verifier import _extract_cited_articles
known = {'消防法·第二十八条','消防法·第二十一条','61号令·第二十一条','61号令·第二十八条'}
ans = '依据《消防法》第二十八条，任何单位不得占用疏散通道；依据61号令第二十一条，单位应当保障疏散通道畅通。'
print(sorted(_extract_cited_articles(ans, known)))
"
```
目标：只输出真实引用的那两条。
提示只给一句：**法规名和条号必须在原文里挨在一起才算数。**

验证：`python3 scripts/trace.py "楼道堆放杂物违反什么规定"`
改对了 `stages` 里的「降级」会消失，耗时从 21 秒掉到 5 秒左右。

**进阶**：再加一条你自己设计的核验规则，写测试让它失败一次、通过一次。

**通过标准**：能说清核验失败后的三级处理（重生成 / 降级 / 拒答）分别在什么条件下触发。

### M4 · 意图分流与微调

**你项目里的对照物**：无。所有问题走同一条链，检索不到就送"无相关参考资料"给大模型自由发挥。

**这里多做了什么**：检索之前先分流成 law / emergency / refuse / chitchat 四类。
分类器是 TF-IDF + LogisticRegression，训练脚本 `scripts/train_intent.py`，
模型落在 `data/models/intent_clf.joblib`。线上是 hybrid：规则先判，模型补漏。

**必背数字**（已与 `intent_clf_metrics.json` / `intent_compare.json` 核对）：

| 项 | 值 |
|----|-----|
| 训练集 | 157 条 |
| 标签分布 | law 122 / emergency 18 / refuse 11 / chitchat 6 |
| test 集 | 32 条（dev 29 条） |
| test 纯规则 | 0.9062 |
| test 纯模型 | 0.9375 |
| test hybrid（线上） | **0.9688** |

这组数字的讲法：**规则和模型单独都不是最优，合起来才最优**，所以线上用 hybrid 是有实证依据的。
同时要主动承认局限——157 条样本、法规类占 78% 的不均衡分布，这正是没上 BERT 的原因之一。
**主动说出局限比被问出来强得多。**

**练习 M4**：
1. 自己重跑一遍 `train_intent.py`，看能不能复现那三个数字。
2. 造 5 个规则和模型会给出不同答案的问题，验证 hybrid 选了谁。
3. 往训练数据里加 10 条你自己编的样本，重训，看指标怎么动。

**通过标准**：能解释 hybrid 里规则和模型谁先说话、为什么这样排。
